Greedy pair merge

The simplest coarsening engine that still feels like CAD

learn_clustering — 03 greedy pair merge

What the coarsener must do

  • Start from singletons — every cell is its own cluster.
  • Repeatedly contract the highest-affinity legal pair into a supernode.
  • Stop at target K, or when no legal positive-weight pair remains.
  • Report the partition and its cutsize (weight still crossing clusters).

There is no undo. Heavy nets should disappear from the cut; weak bridges may stay cut. Capacity (max cluster size) is optional, but when it is on it can block the unconstrained path.

Ranking rules (lock these)

SignalRule
AffinitySum of current edge weight between two clusters (parallels add)
IllegalSkip if affinity ≤ 0, or if |A|+|B| exceeds capacity
PickMaximum affinity
Tie-breakLexicographic cluster labels (sorted member names joined)
CutsizeSum of weights with endpoints in different clusters

Label examples: A, AB, ABC. After each merge, sort remaining clusters by label so later ties stay stable.

On tiny_graph, A–B vs D–E are both weight 5; A–B wins because A < D. After that, AB–C vs D–E are both 5; AB < D so C is absorbed first.

Pitfalls to watch

  • Greedy is myopic: a great first merge can strand you with a bad global cut.
  • Watch illegal merges that violate a size cap — test capacity before ranking, not after.
  • Updating affinities incorrectly after contraction creates silent wrong clusters until goldens fail.
  • A missing lexicographic tie-break makes AB–C versus D–E a coin flip, so tiny_graph tests flake.
